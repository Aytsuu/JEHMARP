## Objective

Update `.github/workflows/deploy-production.yml` so **Deploy Production** is
created only for pushes to `main` containing release-relevant changes. A push
that changes only `README.md`, `web/README.md`, or other documentation must not
start or display a skipped production deployment.

Use GitHub Actions event-level `on.push.paths`, not a job-level `if` condition.
Branch and path filters must remain conjunctive: the automatic production path
is limited to matching files on `main`.

## Scope decisions

- Do not use `paths-ignore` as the primary mechanism. A positive allow-list
  prevents unrelated root files, documentation, and non-production automation
  from accidentally invoking the protected canary and migration pipeline.
- Do not add `web/README.md`, root `README.md`, `context-factory/**`, or other
  documentation paths to the allow-list.
- Do not add `supabase/functions/**` at this time. This workflow does not run
  `supabase functions deploy`; treating an Edge Function-only source change as
  a successful Worker deployment would be misleading. Add that path only in a
  future change that also deploys and verifies Supabase Edge Functions.
- Preserve the existing job-level rollback conditions and all protected
  environment gates. This change must only control workflow creation for
  automatic pushes.
